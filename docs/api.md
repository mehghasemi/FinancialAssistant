# قرارداد API نسخهٔ 0.8.0

همهٔ تاریخ‌های قابل مشاهده و ورودی API شمسی و به‌شکل `YYYY/MM/DD` هستند؛ برای نمونه `۱۴۰۵/۰۶/۲۸`. ماه‌های فیلتر API با کلید `YYYY-MM` ارسال می‌شوند و رابط، آن‌ها را با نام فارسی مانند «شهریور ۱۴۰۵» نشان می‌دهد. تاریخ میلادی فقط در دیتابیس داخلی نگهداری می‌شود. مبلغ‌ها عدد صحیحِ مثبت و در واحد پول تنظیم‌شدهٔ برنامه‌اند.

### خطاها

ورودی نامعتبر پاسخ `422` و پیام فارسی دارد. خطای داخلی پاسخ `500` با `error_id` برمی‌گرداند؛ جزئیات داخلی یا stack trace به رابط کاربری ارسال نمی‌شود.

### ویرایش تعهد

در `PATCH /api/commitments/{id}` عنوان و نوع ضروری‌اند. فیلدهای اختیاری برنامه: `installment_count`، `installment_amount`، `repayment_amount`، `interval_months` و `first_due_date`. حذف فیلد از درخواست یعنی حفظ مقدار فعلی؛ `total_amount: null` مبلغ اطلاعاتی را پاک می‌کند. تغییر تاریخ یا دوره به‌تنهایی هم اعمال می‌شود. برای قسط دارای پرداخت، کاهش مبلغ به کمتر از پرداخت ثبت‌شده یا حذف آن هنگام کاهش تعداد، پاسخ `422` دارد. تغییرات معتبر با حفظ پرداخت‌ها روی اقساط همان تعهد اعمال می‌شوند. شناسهٔ ناموجود `404` دارد. فهرست تعهدات `interval_months`، `first_due_date` و `installment_amount` را نیز برمی‌گرداند؛ دورهٔ نامشخص دادهٔ واردشده می‌تواند null باشد.

در ایجاد و پیش‌نمایش، رابط مبلغ بازپرداخت را دریافت می‌کند. مبلغ قسط آخر برابر `repayment_amount - installment_amount * (installment_count - 1)` است و باید مثبت باشد. برای سازگاری با کلاینت‌های قدیمی، نبود بازپرداخت در API به معنای استفاده از حاصل‌ضرب مبلغ و تعداد اقساط است. کد تعهد و اطلاعات پرداخت، ورودی قابل ویرایش تعهد نیستند.

`GET/PUT /api/settings` تنظیمات بکاپ و `POST /api/backups` ساخت بکاپ دستی را پوشش می‌دهند. بازیابی آفلاین از CLI انجام می‌شود تا دادهٔ برنامهٔ در حال اجرا جایگزین نشود.

در ویرایش جزئی قسط، تغییر مبلغ به همان اندازه بازپرداخت تعهد را تغییر می‌دهد؛ سایر اقساط ثابت‌اند و مبلغ قسط نباید کمتر از پرداخت‌های آن شود. تغییر صرفاً تاریخ یا یادداشت، بازپرداخت را تغییر نمی‌دهد.

رویدادها از GET /api/audit-logs با فیلترهای resource_type و resource_id و صفحه‌بندی before_id و limit خوانده می‌شوند. پاسخ شامل items و next_cursor است. جزئیات جدید دارای before/after هستند؛ سوابق قدیمی فقط اطلاعات ثبت‌شدهٔ زمان خود را دارند. هنگام پاک‌سازی، نوع رویدادهای قبلی با پیشوند archived_ بایگانی می‌شود و مسیر پشتیبان در رویداد پاک‌سازی ثبت می‌شود.

حذف تعهد: DELETE /api/commitments/{id}?confirm=true تعهد و تمام اقساط و پرداخت‌های آن را در یک تراکنش حذف و جزئیات را در رویدادنگاری ثبت می‌کند؛ بدون تأیید پاسخ 422 است. داشبورد پرداخت اقساط را بر اساس ماه سررسید می‌سنجد، upcoming شامل مانده‌های سررسیدشده تا امروز است و current_installments مستقل از ماه انتخابی، ماه جاری را نمایش می‌دهد.


## دارایی‌ها و گزارش مالی (0.19.0)
- `GET/POST /api/assets` و `PATCH /api/assets/{id}`: عنوان، نوع، تاریخ شمسی ثبت، ارزش اولیه و جاری، توضیحات و توضیح تغییر ارزش. مقادیر نامنفی و بر حسب تومان هستند.
- `GET /api/assets/{id}/history`: زمان ثبت تغییر، ارزش قبلی و جدید و توضیح؛ تغییر صرفاً مشخصات، رویداد عمومی دارد ولی ردیف ارزش جدید ایجاد نمی‌کند.
- `POST/PATCH /api/transactions[/{id}]`: افزون بر فیلدهای قبلی، `title`، `counterparty` و `status` (`paid/unpaid/cancelled`، پیش‌فرض paid). PATCH همهٔ فیلدهای فرم را می‌گیرد. حذف: `DELETE /api/transactions/{id}?confirm=true`؛ رویداد قبل از حذف ثبت می‌شود.
- `GET /api/financial-report`: فیلترهای `month` (YYYY-MM شمسی)، `year`، `start_date/end_date` (شمسی، انتهای بازه شامل)، `record_type` (income/expense/installment/commitment)، `category`، `status`، `counterparty`، `search`، `min_amount/max_amount` (تومان). فیلترهای تاریخ در API با هم تقاطع می‌گیرند؛ بازهٔ نامعتبر 422 است.
- خروجی `items` و `summary` است. اقساط با سررسید و تراکنش با تاریخ خودش انتخاب می‌شود؛ شمارهٔ قسط در کل تعهد محاسبه می‌شود، نه فقط بازهٔ انتخابی.
- تعهدها تجمیع اقساط منطبق با فیلتر هستند؛ فیلتر مبلغ و وضعیت بر اقساط مبنا اعمال می‌شود. مجموع تعهدات و اقساط یک مبلغ هستند و با هم جمع نمی‌شوند. خالص = درآمد − هزینه (لغوشده حذف، در انتظار لحاظ)؛ خالص تحقق‌یافته فقط paid؛ مانده پس از اقساط = خالص − کل اقساط سررسیدشده در بازه. این رقم موجودی حساب نیست.
- داشبورد اصلی فقط تراکنش‌های paid را در درآمد و هزینهٔ واقعی لحاظ می‌کند. پرداخت قسط خودکار تراکنش هزینه نمی‌سازد؛ ثبت دوبارهٔ آن به‌عنوان هزینه باعث دوباره‌شماری دستی می‌شود.

- `GET /api/data-status`: نسخهٔ برنامه و زمان آخرین رویداد ثبت‌شدهٔ تغییر اطلاعات یا تنظیمات، به شکل خام و برچسب تاریخ شمسی و ساعت‌ودقیقه؛ خواندن گزارش و تهیهٔ بکاپ این زمان را تغییر نمی‌دهد. در نبود سابقه، زمان null است.

نسخهٔ 0.20.0: گزارش فیلدهای `total_expenses = expense + installment_total` و `monthly_balance = income - total_expenses` دارد؛ هر دو تابع تمام فیلترها هستند. رابط مبلغ تعهدات برنامه‌ریزی‌شده را یک‌بار نمایش می‌دهد و نمای تجمیعی تعهد مستقل از ردیف اقساط است.

- داشبورد همان مبنای گزارش را دارد: درآمد و سایر هزینه‌ها بدون لغوشده‌ها، مجموع هزینه‌ها برابر سایر هزینه‌ها به‌علاوه اقساط سررسید ماه است.
